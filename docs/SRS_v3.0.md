# [SRS] AI 셀프 연말정산 웹 서비스 (정산봄 / SelfTax 2025) 소프트웨어 요구사항 명세서

## 1. 개요 및 설계 원칙

### 1.1 문서 개요
* **문서명**: SelfTax 2025 (정산봄) 소프트웨어 요구사항 명세서 (Software Requirements Specification)
* **적용 세법 기준**: 2025년 귀속 대한민국 소득세법 및 조세특례제한법 (2026년 2월 연말정산 및 5월 종합소득세 신고 기준)
* **시스템 목적**: 근로자가 복잡한 세법이나 세무 대리인 없이 홈택스 간소화 PDF, 근로소득원천징수영수증, 종전근무지 내역, 부속 행정 문서를 업로드하여 세액을 자가 검증·시뮬레이션하고 맞춤형 AI 리포트와 감사 추적(Audit Trail)을 제공받는 웹 서비스 구현.

### 1.2 핵심 아키텍처 및 보안 설계 원칙
1. **수식 연산의 완전한 결정론화 (Deterministic Tax Engine)**:
   - 세액 계산 및 공제 한도 연산 시 거대언어모델(LLM)의 확률적 계산을 전면 배제하고, 순수 Python 및 검증된 클라이언트 계산 엔진에 의해 소득세법 제55조(세율), 조세특례제한법 등의 법정 수식을 100% 결정론적으로 처리한다.
2. **인메모리 PII(개인식별정보) 전면 보호**:
   - 파일 업로드 즉시 인메모리 스트림 상에서 주민등록번호 뒷자리를 마스킹(`[RRN Omitted]` 또는 생년월일 성별 지시자) 처리한다.
   - 원본 파일은 서버 로컬 디스크에 영구 보관하지 않으며, 마스킹되지 않은 고유식별정보의 DB 저장 및 외부 API 전송을 엄격히 차단한다.
3. **세션 기반 상태 관리 및 복수 근무지(중도이직) 지원**:
   - 단일 사용자가 과세연도별 복수 시나리오를 시뮬레이션할 수 있도록 `TaxSession`을 중심으로 데이터 모델을 정규화한다.
   - 당해 연도 이직자의 종(전) 근무지와 주(현) 근무지의 총급여 및 기납부세액(종전근무지는 결정세액)을 N건 등록·합산할 수 있도록 설계한다.
4. **설명 가능한 AI 및 감사 추적 (Explainable Audit Trail & RAG)**:
   - 세액 계산의 모든 중간 연산 단계(과세표준, 산출세액, 감면·공제액, 한도초과액)를 `AuditLog`로 영속화하여 "왜 이 금액이 나왔는가?"에 대한 법적 근거를 제공한다.
   - 국세청 공식 '2025년 귀속 연말정산 신고안내' 지식베이스를 기반으로 출처 페이지 및 관련 법조문을 명시하는 RAG 질의응답을 제공한다.
5. **자료 미등록 시 안전한 기본값 처리 (Zero-State Handling)**:
   - 근로자가 서류를 업로드하거나 공제자료를 입력하지 않은 초기 상태에서는 임의의 가짜 금액이 노출되지 않고 0원으로 정확하게 표기된다.

## 2. 시스템 아키텍처 및 기술 스택

### 2.1 기술 스택 구성

| 계층 (Layer) | 채택 기술 | 비고 및 버전 |

## 4. 세부 기능 요구사항 명세

### 4.1 회원 및 인증 관리 (F-AUTH)
* **F-AUTH-01 (소셜 로그인 및 사용자 프로필 연동)**:
  - 사용자는 구글 소셜 로그인을 통해 로그인할 수 있으며, 로그인 시 `User` 레코드가 조회되거나 자동 생성된다.
  - 로그인한 사용자 성명에서 접미사(`(Google)`)를 제거하여 UI 전반에 실제 근로자 성명으로 반영한다.
  - 비로그인 상태에서도 인트로 랜딩 페이지를 열람하고 기본 시뮬레이션을 진행할 수 있다.
* **F-AUTH-02 (진행 상태 영속화)**:
  - 사용자 ID별로 연말정산 진행 레벨(1:미작성, 2:작성중, 3:작성완료, 4:확인완료)과 작성 완료된 스텝 집합을 로컬 스토리지 및 세션에 영속화한다.

### 4.2 문서 수신 및 개인정보 보호 (F-DOC)
* **F-DOC-01 (다중 PDF 업로드 및 파일 리셋)**:
  - Drag & Drop 영역 및 파일 선택기를 통해 PDF 문서를 업로드한다.
  - 동일한 파일을 연속으로 선택할 때도 `onClick={(e) => e.target.value = ''}` 처리를 통해 즉각 파일 선택 이벤트가 발생하도록 보장한다.
* **F-DOC-02 (PII 인메모리 마스킹)**:
  - 주민등록번호 정규식(?<![0-9])(\d{6})[- ]?([1-8]\d{6})(?![0-9])을 감지하여 뒷자리를 `[RRN Omitted]`로 치환한다.
  - 마스킹되지 않은 개인식별번호는 DB 컬럼이나 외부 로그에 절대 기록되지 않는다.
* **F-DOC-03 (문서 4종 자동 분류)**:
  - 본문 텍스트 내 특정 서식 키워드를 스코어링하여 4종으로 자동 분류한다:
    - `HOMETAX`: 소득·세액공제증명서, 국세청장 직인 등
    - `WITHHOLDING`: 근로소득원천징수영수증, 징수의무자 등
    - `RESIDENT`: 주민등록표등본, 세대주와의 관계 등
    - `FAMILY`: 가족관계증명서, 등록기준지 등
* **F-DOC-04 (증빙 서류 뷰어 모달)**:
  - 업로드 완료된 파일명을 클릭하거나 [서류보기] 버튼 클릭 시, 생성된 Blob URL을 기반으로 브라우저 모달 창을 띄워 원본 서류를 즉시 열람할 수 있도록 한다.

### 4.3 부양가족 인적공제 관리 (F-FAMILY)
* **F-FAMILY-01 (인적공제 등록 및 기본공제 판정)**:
  - 본인은 항상 기본공제 150만 원 대상이다.
  - 배우자: 연간 소득금액 100만 원 이하(근로소득만 있는 경우 총급여 500만 원 이하), 나이 요건 제한 없음.
  - 직계존속: 만 60세 이상 (2025년 기준 1965.12.31 이전 출생), 소득금액 100만 원 이하.
  - 직계비속: 만 20세 이하 (2025년 기준 2005.01.01 이후 출생), 소득금액 100만 원 이하.
  - 형제자매: 만 20세 이하 또는 만 60세 이상, 소득금액 100만 원 이하.
  - 장애인: 나이 요건에 구애받지 않고 소득 요건 충족 시 기본공제 대상.
* **F-FAMILY-02 (추가공제 자동 계산)**:
  - 경로우대: 만 70세 이상(1955.12.31 이전 출생) 1인당 100만 원.
  - 장애인: 1인당 200만 원.
  - 한부모: 배우자가 없는 자로서 기본공제대상 직계비속이 있는 경우 100만 원.

### 4.4 소득 및 원천징수 관리 (F-INCOME)
* **F-INCOME-01 (주근무지 원천징수 처리)**:
  - 업로드된 주근무지 영수증에서 총급여액, 비과세소득, 기납부소득세, 기납부지방소득세를 추출한다.
* **F-INCOME-02 (종전근무지 복수 합산)**:
  - 당해 연도 이직자의 경우 2개 이상의 종전근무지 PDF를 업로드할 수 있다.
  - 종전근무지의 총급여액과 이전 직장의 원천징수영수증상 '결정세액'(기납부세액)을 누적 합산하여 세액 계산 엔진에 전달한다.
* **F-INCOME-03 (종전근무지 UI 카드)**:
  - 등록된 종전근무지 목록 카드 상단에 파싱된 실제 사업체 상호명을 표기하고, 불필요한 분석 완료 박스를 제거하여 심플한 UI를 제공한다.
  - [서류보기] 버튼을 통해 각 근무지별 업로드된 원천징수영수증을 개별 확인한다.

### 4.5 공제 서류 및 수기 지출 관리 (F-DEDUCT)
* **F-DEDUCT-01 (간소화 자료 파싱)**:
  - 홈택스 PDF에서 추출된 신용카드, 의료비, 보험료, 교육비, 주택자금 등의 금액을 각 공제 섹션의 초기값으로 자동 바인딩한다.
* **F-DEDUCT-02 (12대 세부 공제 수기 입력)**:
  - 신용카드·체크카드, 의료비, 교육비, 기부금, 월세액, 연금저축, 개인형IRP, 주택임차차입금, 청약저축, 장기주택저당차입금, 소기업소상공인공제부금(노란우산), 혼인세액공제 항목에 대해 수기 입력 및 개별 증빙 첨부를 지원한다.
* **F-DEDUCT-03 (과다공제 방지 자가진단 팝업)**:
  - 실손보험금 차감 여부, 무주택 세대주 요건, 총급여 기준 요건 등에 대해 '예/아니오' 자가진단 팝업을 제공하여 국세청 과다공제 가산세 위험을 사전에 차단한다.

### 4.6 결정론적 세액 계산 엔진 (F-ENGINE)
* **F-ENGINE-01 (근로소득공제)**:
  - 총급여액 기준 5단계 누진공제율 적용 (최대 2,000만 원 한도).
* **F-ENGINE-02 (과세표준 산정)**:
  - 근로소득금액 = 총급여액 - 근로소득공제
  - 과세표준 = Max(0, 근로소득금액 - 인적공제 - 특별소득공제 - 기타소득공제 + 종합한도초과액)
* **F-ENGINE-03 (산출세액 8단계 세율)**:
  | 과세표준 구간 | 세율 | 누진공제액 |
  |:---|:---|:---|
  | 1,400만 원 이하 | 6% | - |
  | 1,400만 원 초과 ~ 5,000만 원 이하 | 15% | 126만 원 (84만 원 + 누진) |
  | 5,000만 원 초과 ~ 8,800만 원 이하 | 24% | 576만 원 (624만 원 + 누진) |
  | 8,800만 원 초과 ~ 1억 5천만 원 이하 | 35% | 1,544만 원 (1,536만 원 + 누진) |
  | 1억 5천만 원 초과 ~ 3억 원 이하 | 38% | 1,994만 원 (3,706만 원 + 누진) |
  | 3억 원 초과 ~ 5억 원 이하 | 40% | 2,594만 원 (9,406만 원 + 누진) |
  | 5억 원 초과 ~ 10억 원 이하 | 42% | 3,594만 원 (1억 7,406만 원 + 누진) |
  | 10억 원 초과 | 45% | 6,594만 원 (3억 8,406만 원 + 누진) |
* **F-ENGINE-04 (세액공제 및 결정세액)**:
  - 근로소득세액공제: 산출세액 130만 원 이하 55%, 초과분 30% (총급여 구간별 50만~74만 한도).
  - 중소기업 취업 청년 감면: 산출세액의 90% (연 200만 원 한도).
  - 자녀세액공제: 1명 15만, 2명 35만, 3명 이상 35만 + (초과 인원 × 30만).
  - 혼인세액공제: 50만 원 (부부 각각 적용 가능).
  - 월세액 세액공제: 총급여 8,000만 원 이하 무주택자, 연 1,000만 원 한도 내 15%~17%.
  - 결정세액 = Max(0, 산출세액 - 세액공제·감면 합계).
* **F-ENGINE-05 (차감징수세액 및 Zero-State)**:
  - 차감징수세액 = 결정세액 - 기납부세액 (음수면 환급, 양수면 추가납부).
  - 업로드된 서류나 입력 내역이 전혀 없는 경우 모든 결과 금액을 `0원`으로 정확히 반환한다.

### 4.7 결과 분석 및 보고서 (F-REPORT)
* **F-REPORT-01 (예상세액 조회 화면)**:
  - 차감납부(환급)세액 결과에 따라 상단 캘린더 이모지(웃는 표정 vs 긴장한 표정)와 미니 계산기 화면(+/- 금액)을 동적으로 렌더링한다.
  - 금액 0원 시 부호 없이 `0원`으로 명확히 표기.
* **F-REPORT-02 (AI 연말정산 결과 리포트)**:
  - 환급 시 지갑&환급금 2D 일러스트, 추가납부 시 세금고지서 2D 일러스트를 자동 스위칭한다.
  - 상단 안내 배너에서 불필요한 단정적 문구를 배제하고 분석 성과를 직관적으로 전달한다.
* **F-REPORT-03 (미공제 항목 심층 분석)**:
  - 의료비: 총급여 3% 미달 시 사용금액과 기준액까지 부족한 금액을 프로그레스 바로 시각화.
  - 신용카드: 총급여 25% 미달 시 부족액 및 공제 제외 안내.
  - 보장성보험: 연 100만 원 한도 초과 시 불공제 금액 명시.
* **F-REPORT-04 (차년도 절세 시뮬레이션)**:
  - 자녀 출산, 혼인 계획, 월세 공제 한도 확대, 청약통장 월 인정액 상향(10만->25만) 카드 슬라이더(4장) 제공.

### 4.8 지식 검색 및 부가 서비스 (F-RAG)
* **F-RAG-01 (국세청 가이드 RAG 검색)**:
  - 사용자의 세무 질의(예: "월세 공제 요건", "실손보험 의료비")에 대해 국세청 안내서 출처 페이지와 관련 법률 조문을 명시하여 답변을 제공한다.
* **F-RAG-02 (구비서류 및 이용 가이드)**:
  - 공제 항목별 필수 제출 서류 및 발급처 링크 안내, 서비스 이용 가이드, 회사 소개 페이지 제공.

## 5. 데이터베이스 스키마 명세 (Database Entities)

### 5.1 엔티티 정의 요약

| 테이블명 | ORM 클래스 | 설명 | 관계 (Relationships) |
|:---|:---|:---|:---|
| `users` | `User` | 서비스 사용자 계정 (UUID PK) | 1:N `tax_sessions` |
| `tax_sessions` | `TaxSession` | 연말정산 작업 세션 (UUID PK) | N:1 `users`, 1:N `documents`, `workplace_incomes`, `dependents`, 1:1 `expense_deductions`, `tax_results` |
| `documents` | `Document` | 업로드된 증빙 문서 정보 및 JSON | N:1 `tax_sessions` |
| `dependents` | `Dependent` (`FamilyMember`) | 부양가족 인적사항 및 적격성 플래그 | N:1 `tax_sessions` |
| `workplace_incomes` | `WorkplaceIncome` | 주/종전 근무지별 총급여 및 기납부세액 | N:1 `tax_sessions` |
| `expense_deductions` | `ExpenseDeduction` (`Deduction`)| 항목별 지출 공제액 및 원본 JSON | 1:1 `tax_sessions` |
| `tax_results` | `TaxResult` | 최종 과세표준, 산출세액, 환급/납부액 | 1:1 `tax_sessions`, 1:N `audit_logs` |
| `audit_logs` | `AuditLog` | 단계별 계산 근거, 수식, 중간 스냅샷 | N:1 `tax_results` |

### 5.2 데이터 무결성 규칙
- 모든 테이블의 기본키(PK)는 `UUIDv4` 형식을 사용한다.
- 모든 외래키(FK)는 상위 세션/결과 삭제 시 연쇄 삭제(`ondelete="CASCADE"`)된다.
- 주민등록번호는 항상 마스킹된 토큰(`masked_identifier`) 형태로만 저장된다.

## 6. REST API 인터페이스 규격 (API Endpoints)

* **Base URL**: `http://localhost:8000/api/v1`
* **모든 엔드포인트는 직관성을 위해 `/upload`와 `/tax/upload`, `/calculate`와 `/tax/calculate` 양방향 라우팅을 지원한다.**

| 메서드 | 엔드포인트 | 요청 형식 | 주요 응답 페이로드 | 비고 |
|:---|:---|:---|:---|:---|
| `POST` | `/sessions` | JSON (`tax_year`, `is_sme_youth`) | `session_id`, `status`, `created_at` | 세션 발급 |
| `GET` | `/sessions/{id}` | Path Parameter | 세션 진행 상태 및 사용자 정보 | 상태 확인 |
| `POST` | `/upload` | `multipart/form-data` | `List[DocumentUploadResponse]` | PDF 업로드, PII 마스킹, 분류 |
| `POST` | `/ocr` | JSON (`document_id`, `raw_text`) | `doc_type`, `confidence`, `parsed_json` | 문서 4종 분류 및 엔티티 추출 |
| `POST` | `/validate` | JSON (`session_id`, `dependents`) | `is_valid`, `warnings`, `errors`, `details` | 부양가족 및 중도이직 검증 |
| `POST` | `/calculate` | JSON (`session_id`, `override_salary`) | `total_salary`, `taxable_income`, `refund_amount` | 정밀 세액 계산 및 AuditLog 저장 |
| `POST` | `/rag/search` | JSON (`query`, `section`) | `answer`, `source_page`, `legal_basis` | 국세청 가이드 출처 해설 |
| `GET` | `/result/{id}` | Path Parameter | `total_gross_salary`, `final_refund_amount`, `logs` | 최종 정산 결과 및 세부 명세 |
| `GET` | `/audit/{id}` | Path Parameter | `total_steps`, `logs: List[AuditLogItem]` | 7단계 계산 과정 Audit Trail |
| `POST` | `/checklist` | - | `questions: List[ChecklistQuestion]` | 과다공제 방지 자가진단 문항 |
| `GET` | `/report/pdf/{id}`| Path Parameter | `application/pdf` 바이너리 스트림 | 시뮬레이션 결과지 PDF 다운로드 |

## 7. 비기능적 요구사항 (Non-Functional Requirements)

### 7.1 성능 (Performance)
* **단일 PDF 파싱 및 마스킹**: 3초 이내 완료.
* **세액 계산 엔진 연산**: 50ms 이내 결정론적 연산 완료.
* **API 평균 응답 시간**: 300ms 이내 (파일 업로드 제외).
* **프론트엔드 실시간 반응성**: 입력값 변경 시 100ms 이내 실시간 예상세액 재계산 렌더링.

### 7.2 보안 및 규정 준수 (Security & Privacy)
* **개인정보보호법 준수**: 주민등록번호 등 고유식별정보의 원본 저장을 기술적으로 원천 차단.
* **인메모리 버퍼링**: 업로드된 바이너리는 메모리에서 파싱 후 즉시 가비지 컬렉션 처리.
* **CORS 및 인증 보안**: 승인된 프론트엔드 오리진(`http://localhost:5173`)만 접근 허용, Bearer 토큰 연동 구조 유지.

### 7.3 사용성 및 UI/UX (Usability)
* **모바일 및 태블릿 최적화**: PC 환경에서는 모던 와이드 인트로 모달(max-w-1120px) 및 중앙 집중형 태블릿 앱 프레임(max-w-768px), 모바일에서는 100vw 전체 화면 최적화.
* **상태 전이 피드백**: 파일 재선택 시 리셋 처리, 서류보기 모달 팝업, 단계별 프로그레스 바 상시 노출.
* **디자인 시스템 일관성**: Slate, Indigo, Emerald, Rose 계열의 정밀 HSL 컬러 팔레트와 부드러운 트랜지션 애니메이션 적용.
